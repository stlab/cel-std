# CEL f64 standard library implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the public C++ f64 CEL standard library, excluding powi.

**Architecture:** A compiled installer registers exact numeric signatures in
cel-parser. Private standard-library adapters preserve Rust numeric semantics;
cel-runtime owns and executes the emitted operations.

**Tech stack:** C++20, CMake, cpp-library, CPM, doctest, Doxygen.

**Spec:** `docs/superpowers/specs/2026-11-13-cel-std-design.md`

## Global constraints

- Repository: public `stlab/cel-std`; GitHub account: `sean-parent`.
- Use C++20, cpp-library, and CPM with verified pinned dependencies.
- Expose `<cel/std.hpp>`, `cel::std`, and `void cel::stdlib::install(cel::op_lookup&)`.
- Retain only f64 signatures; exclude powi; retain structural sin_cos tuples.
- Preserve operation names, operand order, errors, and Rust floating-point semantics.
- Work on `feat/f64-port` in `.claude/worktrees/f64-port`, never directly on main.
- Every introduced type and function has an adjacent contract and unit coverage.

## Review focus

- Ambient rounding modes must not change ties-to-even results: test all four modes.
- Clamp must reject NaN bounds without invoking a C++ library precondition violation.
- Negative zero must retain operation-specific signs: assert signbit and infinities.
- Installed consumers must resolve parser/runtime without local source-tree paths.
- Programs must retain usable callbacks after parser and lookup destruction.

## File structure

- `CMakeLists.txt`, `cmake/CPM.cmake`: library, pinned dependencies, tests, docs.
- `include/cel/std.hpp`: public installation contract and shared example.
- `src/std.cpp`: persistent registrations and numeric adapters.
- `tests/std_test.cpp`: contract-derived numeric and parser integration tests.
- `tests/consumer/`, `tests/consumer.cmake.in`: independent package/source consumers.
- `examples/example.cpp`: runnable tutorial example.
- `README.md`, `docs/tutorial.md`, `docs/reference.dox`: orientation, tutorial, reference.
- `.github/workflows/ci.yml`, `.gitignore`, `LICENSE`, formatting configuration:
  repository conventions and repeatable checks.
